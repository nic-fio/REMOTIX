How it works

One server, one web page. Nothing else.

REMOTIX runs on your Linux server and serves its own page. Whoever connects needs only a modern browser: Windows, macOS, Linux, Android, ChromeOS.

A real desktop per user

GNOME, KDE Plasma, XFCE or LXQt. Each user gets their own session on the same server, isolated from the others.

It waits for you

Close the browser, change device, come back tomorrow: the session keeps running and your windows are still there.

Fast on a modest server

The graphics card compresses the screen in H.264, and the browser decodes it in hardware. Video, audio and clipboard included.

Why REMOTIX

Built for Linux, not adapted to it.

Remote desktop protocols were designed around Windows. REMOTIX speaks its own protocol over WebTransport, straight to the Linux compositor.

Requirements

What you need.

The server

A Linux machine, physical or virtual, with internet access for the license. Debian, Ubuntu, Fedora and their families. An Intel, AMD or NVIDIA graphics card is recommended; without one REMOTIX encodes in software and declares it.

Whoever connects

Chrome or Edge on Windows, Linux and Android; Firefox on Linux. Nothing to install, no plug-in, no account on our side.

FAQ

Questions.

Can I use REMOTIX on Windows servers?

No. REMOTIX serves Linux desktops only. You can connect from Windows, though: any modern browser will do.

What happens if my server loses internet access?

REMOTIX keeps working for 14 days from the last successful license check, and tells the administrator how many days are left.

Does the license stop my server if it expires?

Only REMOTIX stops, after 14 days of grace. SSH and local logins are never touched, and running desktops stay alive until you renew.

I'm moving to a new server. Do I need a new key?

No. Copy REMOTIX over and switch the old server off: the license follows the installation.
