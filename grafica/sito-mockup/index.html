How it works

One server. Every user. Any browser.

REMOTIX is the server half of remote desktop: it runs on the Linux machine, creates a desktop session for each user who signs in, and serves the page they connect with.

Why REMOTIX

Built for Linux, not adapted to it.

The desktop waits for you

Close the browser, change device, come back tomorrow: the session keeps running and your windows are still there.

Video from the graphics card

Intel, AMD or NVIDIA encode the screen in H.264 or HEVC; the browser decodes it in hardware. Audio and clipboard included.

Safe defaults

Always encrypted, root excluded, three wrong passwords and the address is out for twelve hours. Nobody can switch the server off from a session.

FAQ

Questions.

How many users can one server serve?

It depends on the CPU, the graphics card and what users do: office work and video are very different loads. REMOTIX admits a new session only while the server can carry it, and refuses with the reason when it cannot. The sizing guide in the documentation has measurements on real hardware.

Which accounts can sign in?

REMOTIX uses the same PAM stack as SSH. If your users can already log in to the server with SSH, through local accounts or a directory, they can open a desktop. Root is always excluded.

What happens when a user closes the browser?

The session keeps running. They can reconnect from the same or another device and find their windows as they left them. After 60 minutes without input the session is closed cleanly.

Is it really free, even for a company?

Yes. Using REMOTIX costs nothing, at home or at work. A license is needed only to sell it, build it into a product, or sell access to desktops served by it.

Is REMOTIX open source?

The source code is visible, and you can build and modify it for yourself. It is not "open source" in the OSI sense, because selling it and distributing modified copies are reserved.

Does REMOTIX phone home?

No. There is no account, no key and no license check: once installed, REMOTIX works without internet access.
