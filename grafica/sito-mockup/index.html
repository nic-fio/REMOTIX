Browser-based VDI for Linux

Linux desktops for your whole team, served from one host.

REMOTIX is a session-based VDI server. Every user gets their own full desktop on a shared Linux host, encoded by the GPU and delivered to the browser. No hypervisor, no broker, no client to deploy, no per-seat fees.

See it

A real desktop, in a browser tab.

Not a picture of a desktop: the session runs on the host, the GPU encodes it, the browser decodes it in hardware. Keyboard, mouse, touch, audio and clipboard included.

Sessions that wait

Close the laptop. Open the tablet.

The desktop belongs to the session, not to the connection. Disconnect, change device, change network: the windows are where you left them. Idle sessions are closed cleanly after an hour without input.

GPU encoding

The graphics card does the heavy lifting.

Each session is encoded in H.264 or HEVC on the host's Intel, AMD or NVIDIA GPU and decoded by the browser in hardware. The CPU stays free for the applications your users run.

Session-based VDI

One system to look after, not one VM per user.

Every user gets a session on a shared Linux host: one operating system to update, one set of applications to install, a fraction of the memory a virtual machine per user would need. No hypervisor, no broker.

For administrators

Built to be left running.

  • Same sign-in as SSH. REMOTIX follows the host's PAM stack; root is always excluded.
  • TLS, always. Its own certificate, renewed by itself, or yours.
  • Three strikes. Three failed sign-ins from an address and it is out for 12 hours.
  • Admission control. When the host is full a new session is refused with the reason, never squeezed in.
  • Nobody switches the host off. Shutdown and reboot are removed from every session.
  • Your system stays yours. Packages from your distribution's repositories, a clean uninstall.

FAQ

Questions.

How many users can one host serve?

It depends on the CPU, the graphics card and what users do: office work and video are very different loads. REMOTIX admits a new session only while the host can carry it, and refuses with the reason when it cannot. The sizing guide in the documentation has measurements on real hardware.

Can users sign in with our directory accounts?

REMOTIX uses the same PAM stack as SSH. If your users can already log in to the host with SSH, through local accounts or a directory, they can open a desktop. Root is always excluded.

What happens when a user closes the browser?

The session keeps running. They can reconnect from the same or another device and find their windows as they left them. After 60 minutes without input the session is closed cleanly.

Is it really free, even for a company?

Yes. Using REMOTIX costs nothing, at home or at work. A license is needed only to sell it, build it into a product, or sell access to desktops served by it.

Is REMOTIX open source?

The source code is visible, and you can build and modify it for yourself. It is not "open source" in the OSI sense, because selling it and distributing modified copies are reserved.

Does REMOTIX phone home?

No. There is no account, no key and no license check: once installed, REMOTIX works without internet access.
