REMOTIX for Debian 13

Your Debian 13 desktop in a web browser, for several users at once, on XFCE, LXQt, GNOME or KDE Plasma. One .deb package, installed with apt. This page has everything that is specific to Debian 13: the installer, the requirements, what was verified, the manuals and the history.

Installer

Install REMOTIX 1.0.0 on Debian 13

The installer is a single Debian package, remotix_1.0.0-1+deb13_amd64.deb. There is no other installer program.

1. Download the package

Download remotix_1.0.0-1+deb13_amd64.deb

The same file is also on GitHub: release 1.0.0.

SHA-256 of the package:

d2ec4771f3fe9e94fe9a736649d4b2fa100820c5b61ef276767e21e24d504f61

Check it before installing:

sha256sum remotix_1.0.0-1+deb13_amd64.deb

2. Install and start

sudo apt install ./remotix_1.0.0-1+deb13_amd64.deb
sudo systemctl enable --now remotix

Use apt install as written: apt reads what REMOTIX needs from the package and installs it from Debian's repositories. dpkg -i does not fetch anything and leaves the installation incomplete.

The package installs the service switched off; the second command is what turns it on. Then, from any device on your network, open https://machine:7447 (the name or the address of the machine) in the browser and sign in with the user name and password of a user of that machine.

The first time on each device the browser warns about the certificate: the machine makes its own. Accept it after checking the address.

If the installation stops

The package refuses to install on a machine without a video card, and tells you why. It also refuses if an account named «remotix» already exists and belongs to a person: rename or remove that account, then install again. If the card is there but cannot encode video, the installation completes and says so: REMOTIX would not work on that machine.

Remove it

sudo apt remove remotix
sudo apt purge remotix

remove takes REMOTIX off the machine and keeps its settings; purge removes the settings as well. Both close the remote desktops of anyone connected: warn them first. Removal and purge were tried on a Debian 13 virtual machine. The packages apt installed with REMOTIX stay; sudo apt autoremove lists them.

Requirements

What Debian 13 needs

  • Debian 13 “trixie”, 64-bit PC (amd64).
  • One of the four desktops installed.
  • A video card that encodes video. Intel and AMD cards do it through VA-API, with the drivers in Debian's own repositories. NVIDIA: the route for it (Vulkan Video) is written, but it has never been tried on a real NVIDIA card, so whether it works is not known. In a virtual machine REMOTIX works only if the real video card is passed through to the machine.
  • A browser on the device you connect from: Chrome or Edge, or Firefox on a computer.
  • Port 7447, TCP and UDP, open between the device and the machine.
  • Supported limits: up to 3K resolution (the size you get depends on the device and browser you connect from) and up to 8 users at the same time.

What it deliberately does not do: no encoding on the processor; no power off, restart, suspend or hibernate from a desktop, not even at the machine; local sign-in comes first (a user signed in at the machine is refused remotely, and a local sign-in closes that user's remote desktop, with its programs); no unblock command for the administrator (a blocked address is freed by the wait: 15 minutes, then 1 hour, then 12 hours); meant for your own network or a VPN. The home page explains each one.

What was verified

What was tried on Debian 13, and what was not

Tested on all four desktops

One test machine per desktop, with Chrome as the browser and, for part of the checks, Firefox:

  • sign-in and desktop, mouse, keyboard with accents
  • text clipboard in both directions, sound, video
  • leaving and coming back to the same session; Log Out ending the session for real
  • several users at the same time, and one leaving while another keeps working
  • a restart of the service closes the desktops cleanly and the next sign-in gets a new one; a network that drops leaves the desktop waiting
  • the defences of the sign-in (wrong passwords, blocked addresses)

The clipboard and the video measurements were checked with Chrome; the clipboard with Firefox is not yet verified.

The package

  • installation, removal and purge, checked on the four desktops and on a real Debian 13 virtual machine
  • the AppArmor profile, a reboot and the removal, on that virtual machine
  • the refusal on a machine without a video card
  • signing in at the machine's own login screen while a remote desktop is open, tried by hand on the real login screens of all four desktops: the remote desktop is closed and the local sign-in goes through at the first attempt
  • a trial by the author with a Samsung DeX screen on GNOME: clipboard, sound, video and window resizing

Known limits of this version

  • The AppArmor profile is in observation mode (it reports, it does not block). It was checked up to the connection; it has not yet been observed during a full session on a machine with a video card.
  • On XFCE, a Log Out requested while the desktop is still starting is ignored by the desktop.
  • On XFCE the background of the remote desktop may be black instead of your wallpaper (cosmetic; cause not yet established).
  • On GNOME, the password window for administrator actions in graphical programs (pkexec) has not been verified; if it does not appear, use sudo in a terminal.
  • Touch has been tried only on a simulated phone, not yet on a real one.
  • The tests never had more than three users connected at once; 8 is the declared limit.
  • NVIDIA cards have not been tried (see Requirements). Windows and Safari have not been tried.

Measurements

What was measured on this version

Figures from the automated tests of the code released as 1.0.0, on 17 Nov 2026: four Debian 13 containers, one per desktop, running together on one server with an Intel UHD 770 and an AMD RX 6800 (the logs do not say which card encoded); H.264 encoded in hardware; the browser ran on the same machine, with no network in between, at 1344×768. These are figures of that test bench, not of a particular laptop or phone, and they are not a promise.

How to read it. The frame rate is what the page painted for an animation running at 60 Hz on the desktop; with two users at once each one kept the same rate as alone. GNOME was lower than the others in this test (about 39 frames per second); the reason has not been established. The delay is measured with a counter on the desktop, from its last change to the moment the new value is on screen in the browser; it is read from screenshots that take about 49 ms each, so it is not an end-to-end latency figure. Sound arrives about 0.3 seconds after the picture: REMOTIX keeps the sound slightly behind on purpose, so that it does not break up.

History

Changes in REMOTIX for Debian 13

1.0.0 — the first version for Debian 13

What it contains:

  • Four desktops: XFCE, LXQt, GNOME and KDE Plasma, each on Wayland.
  • Several users at once, each with their own desktop; the session survives closing the browser or a dropped network; Log Out, a restart of the service, or a sign-in at the machine itself closes it.
  • Video encoded by the video card (Intel and AMD, through VA-API), sound, text clipboard, keyboard with accents, mouse.
  • Sign-in defences: the address is blocked for a while after too many wrong passwords.
  • One .deb package, installed with apt; the service is installed switched off. It refuses to install on a machine without a video card.
