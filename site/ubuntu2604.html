REMOTIX for Ubuntu 26.04

Your Ubuntu 26.04 desktop in a web browser, for several users at once, on Ubuntu (GNOME), Kubuntu (KDE Plasma), Xubuntu (XFCE) or Lubuntu (LXQt). One .deb package, installed with apt. This page has everything that is specific to Ubuntu 26.04: the installer, the requirements, what was verified, the manuals and the history.

Installer

Install REMOTIX 1.0.0 on Ubuntu 26.04

The installer is a single Debian package, remotix_1.0.0-1+ubuntu26.04_amd64.deb. There is no other installer program. The same package serves Ubuntu, Kubuntu, Xubuntu and Lubuntu 26.04.

1. Download the package

Download remotix_1.0.0-1+ubuntu26.04_amd64.deb

SHA-256 of the package:

08772d85d0b13298ee211e43b61ecf7295a3cce1713bef933dcadee4f46736ab

Check it before installing:

sha256sum remotix_1.0.0-1+ubuntu26.04_amd64.deb

2. Install and start

sudo apt install ./remotix_1.0.0-1+ubuntu26.04_amd64.deb
sudo systemctl enable --now remotix

Use apt install as written: apt reads what REMOTIX needs from the package and installs it from Ubuntu's archive. dpkg -i does not fetch anything and leaves the installation incomplete. Do not add --no-install-recommends: the recommended packages include the video card's drivers and, on Xubuntu and Lubuntu, the compositor.

The package installs the service switched off; the second command is what turns it on. Then, from any device on your network, open https://machine:7447 (the name or the address of the machine) in the browser and sign in with the user name and password of a user of that machine.

The first time on each device the browser warns about the certificate: the machine makes its own. Accept it after checking the address. If the machine's firewall is on (on Ubuntu it is installed but off), open port 7447 for TCP and UDP; the package adds a ufw profile called REMOTIX for that.

If the installation stops

The package is written to refuse to install on a machine without a video card, and to tell you why. It also refuses if an account named «remotix» already exists and belongs to a person: rename or remove that account, then install again. If the card is there but cannot encode video, the installation completes and prints a warning: REMOTIX would not work on that machine. The two refusals were read from the package's script; they were not tried on Ubuntu 26.04, because every machine used for this release had a video card.

Remove it

sudo apt remove remotix
sudo apt purge remotix

remove takes REMOTIX off the machine and keeps its settings; purge removes the settings as well. Both close the remote desktops of anyone connected: warn them first. The packages apt installed with REMOTIX stay; sudo apt autoremove lists them. Removal and purge were not run on an Ubuntu 26.04 machine for this release: the User Manual describes them from the package's scripts.

Requirements

What Ubuntu 26.04 needs

  • Ubuntu 26.04, 64-bit PC (amd64), or one of its flavours: Ubuntu (GNOME), Kubuntu (KDE Plasma), Xubuntu (XFCE), Lubuntu (LXQt). Other versions of Ubuntu are not covered.
  • One of the four desktops installed, and only one: machines with several desktops installed together are not supported. REMOTIX does not install a desktop.
  • The universe part of Ubuntu's archive switched on, as it is on a normal installation: some of the packages REMOTIX asks for are there.
  • A video card that encodes video. Intel and AMD cards do it, with the drivers in Ubuntu's own archive. For this version only an AMD Radeon was used on Ubuntu 26.04; Intel was not tried. NVIDIA: the route for it (Vulkan Video) is written, but nobody has seen it work on Ubuntu, so do not rely on it. In a virtual machine REMOTIX works only if the real video card is passed through to the machine.
  • A browser on the device you connect from: Chrome or Edge, or Firefox on a computer.
  • Port 7447, TCP and UDP, open between the device and the machine.
  • Supported limits: up to 3K resolution (the size you get depends on the device and browser you connect from) and up to 8 users at the same time. No more than three users were tried together on Ubuntu 26.04.

What it deliberately does not do: no encoding on the processor; no power off, restart, suspend or hibernate from a desktop, not even at the machine; local sign-in comes first (a user signed in at the machine is refused remotely, and a local sign-in closes that user's remote desktop, with its programs); no unblock command for the administrator (a blocked address is freed by the wait: 15 minutes, then 1 hour, then 12 hours); meant for your own network or a VPN. The home page explains each one.

What was verified

What was tried on Ubuntu 26.04, and what was not

Everything below was done on 18 and 19 November 2026, with an AMD Radeon video card, on the package of that time. The package offered here differs from the one of the full round in one rule (restart is refused also to a user at the machine), added on 20 November and checked on the GNOME virtual machine only; the full round was not repeated.

Automatic tests

  • rounds of the test suite in containers, one per desktop (Ubuntu, Kubuntu, Xubuntu, Lubuntu), with Chrome and Firefox on Linux
  • a full round on a virtual machine with the real video card passed through, on GNOME (Ubuntu): sign-in, desktop, mouse, keyboard, clipboard, sound, video, session life cycle, several users, sign-in defences. It had two failures, explained in the Technical Manual: one is by design, the other a false alarm of the test bench; one check was blocked (the sound of Firefox, repeated and passed) and three were skipped
  • on the virtual machines of the other three desktops only a short run: start with the card, a sign-in that reaches the desktop with video, exit

By hand and on real systems

  • the four desktops in virtual machines, from Linux and from Android (phone and tablet): sign-in, work, leaving and coming back to the session, at different window sizes
  • the four live systems (Ubuntu 26.04.1, Kubuntu 26.04.1, Xubuntu 26.04, Lubuntu 26.04) on real hardware: the sign-in worked; at the first attempt on Ubuntu and Kubuntu, while for Xubuntu and Lubuntu there is only the author's report
  • signing in at the machine's own login screen while a remote desktop is open: tried on the live Ubuntu and Kubuntu, where the remote desktop is closed
  • on GNOME, in the first test environment (a container): Chrome from Windows, Linux and Android (tablet, Samsung DeX), with leaving and coming back, sound, video, clipboard and different window sizes
  • programs of snap and some of Ubuntu's own (the live installer, Firmware Updater, Security Center, App Center) open in the remote GNOME desktop without error

Known limits of this version

  • The full round of tests was run on GNOME only. Kubuntu, Xubuntu and Lubuntu were checked by a short run and by hand.
  • The package offered here differs from the one of the full round in one rule (restart is refused also to a user at the machine), added on 20 November and checked on the GNOME virtual machine only; the full round was not repeated.
  • Removal and purge, and the package's two refusals, were not run on an Ubuntu 26.04 machine: they are described from the package's scripts.
  • The AppArmor profile is in observation mode (it reports, it does not block); enforce mode was not tried.
  • The sign-in at the machine's own screen was not tried on Xubuntu and Lubuntu. On Kubuntu, a remote desktop takes about eleven seconds to close when somebody signs in at the machine.
  • Intel video cards and NVIDIA cards have not been tried on Ubuntu 26.04. Safari has not been tried; Firefox on Windows has not been tried and Firefox on Android is not supported; the clipboard with Firefox is not verified.
  • On GNOME, programs that ask for the administrator's password in a window (pkexec) do not start in a remote session: use sudo in a terminal.
  • On XFCE, a Log Out chosen while the desktop is still starting is ignored, a window corner hidden under the panel cannot be dragged, and the wallpaper chosen at the machine does not pass to the remote screen.
  • From Chrome on an Android phone, small jerks in the video were seen on GNOME; the cause is not found.
  • No measurements of picture quality, frame rate or delay exist yet for Kubuntu, Xubuntu and Lubuntu, and no figure for how many users a machine can serve.

History

Changes in REMOTIX for Ubuntu 26.04

1.0.0 — the first version for Ubuntu 26.04

What it contains:

  • Four desktops: Ubuntu (GNOME), Kubuntu (KDE Plasma), Xubuntu (XFCE) and Lubuntu (LXQt), each on Wayland.
  • Several users at once, each with their own desktop; the session survives closing the browser or a dropped network; Log Out, a restart of the service, or a sign-in at the machine itself closes it.
  • Video encoded by the video card (Intel and AMD, through VA-API; Vulkan Video on AMD), sound, text clipboard, keyboard with accents, mouse.
  • Sign-in defences: the address is blocked for a while after too many wrong passwords.
  • One .deb package, installed with apt; the service is installed switched off. It is written to refuse to install on a machine without a video card.
